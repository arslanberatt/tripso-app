# Internationalization (i18n)

The app ships in **English (`en`)** and **Turkish (`tr`)**. Language is detected
from the device once at startup; unsupported devices fall back to English. Both
languages are LTR, so there is **no RTL handling**.

Built on `i18next` + `react-i18next` + `expo-localization` (Expo SDK 56). All
strings — UI labels **and** mock content — resolve through `t()`.

## The pieces

| File | What it is |
| --- | --- |
| `src/i18n/index.ts` | i18next init (side-effect). Static `resources`, synchronous init |
| `src/i18n/detect-language.ts` | `detectLanguage()` → `'tr'` or `'en'` from `getLocales()` |
| `src/i18n/content.ts` | `slugify()` + helpers that resolve **mock content** to translations |
| `src/i18n/locales/<lng>/<ns>.json` | the translation tables (`en` is canonical) |

## How it boots

`src/app/_layout.tsx` imports `'@/i18n'` as its **first** line. That side-effect
runs `i18next.init()` synchronously (`initAsync: false`, `react.useSuspense:
false`), so `t()` is ready before any screen renders — no empty first frame, no
Suspense boundary, **no `<I18nextProvider>`** needed.

```ts
// _layout.tsx
import '@/i18n'; // must stay first
```

## Namespaces

Strings are split into five namespaces (the default is `common`):

| Namespace | Holds |
| --- | --- |
| `common` | shared UI: tabs, generic actions, a11y labels |
| `auth` | login / register / social / field labels |
| `home` | home, destination detail, coming-soon stubs, trip stub |
| `onboarding` | onboarding footer (slide text lives in `content`) |
| `content` | **mock data**: destinations, tags, highlights, experiences, onboarding slides |

## Using translations in UI

Call `useTranslation()` and reference keys as `t('<ns>:<dot.path>')`:

```tsx
import { useTranslation } from 'react-i18next';

function Example() {
  const { t } = useTranslation();
  return <ThemedText>{t('home:topDestinations')}</ThemedText>;
}
```

- **Interpolation:** `t('home:greeting', { name })` → `"Hi, Ada 👋"`. Emoji are
  plain characters.
- **Plurals:** i18next `_one`/`_other` suffixes with `{{count}}`, e.g.
  `t('home:notificationsUnread', { count })`.
- **Default-prop rule:** never call `t()` at module scope (it runs before init
  and is not reactive). For self-contained components, take the prop as
  `undefined` and resolve inside: `placeholder ?? t('auth:fields.email')`.
- **Native tab labels:** `TabsLayout` calls `useTranslation()` and feeds
  `<NativeTabs.Trigger.Label>{t('common:tabs.home')}</...>`.

## Translating mock content

Mock objects (`src/mocks/*`) keep their **API-shaped English strings** — we do
**not** add parallel `tr`/`en` fields. Instead, render sites resolve through the
helpers in `content.ts`, which derive a key via `slugify()` and pass the mock
string as `defaultValue` (so a missing key degrades gracefully to English):

```ts
// content.ts
destinationName(d);        // content:destinations.<slug>.name
tagLabel('Beach');         // content:tags.beach   (shared dictionary)
highlightLabel(h.label);   // content:highlights.<slug>
experienceTitle(e);        // content:experiences.<slug>.title
experienceDuration(e);     // content:experiences.durations.<slug>
```

These helpers use the default i18next instance, so they re-resolve on the next
render. Call them inside a component that also uses `useTranslation()` so a
language change re-renders and re-translates.

## Adding a new key

1. Add the key to **every** locale file for its namespace — both
   `locales/en/<ns>.json` and `locales/tr/<ns>.json`.
2. Reference it with `t('<ns>:<dot.path>')`.

`en` is the source of truth; if a `tr` key is missing, that string falls back to
English at runtime (and content helpers fall back to the mock string).

## Adding a new language

1. Create `src/i18n/locales/<lng>/{common,auth,home,onboarding,content}.json`.
2. Import them and add the `<lng>` block to `resources` in `index.ts`.
3. Extend `SUPPORTED_LANGUAGES` (and the `detectLanguage()` mapping) in
   `detect-language.ts`.

## Runtime language switching

No UI toggle ships yet, but the architecture supports it: calling
`i18next.changeLanguage('tr')` re-renders every `useTranslation()` consumer. The
storage key `@tripso/language` (`src/storage/keys.ts`) is reserved for persisting
a user's explicit choice later.
